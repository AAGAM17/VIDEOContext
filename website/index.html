Video your agents can cite.

VIDEOContext reads a recording once (speech, on-screen text, scenes and events) and writes a timestamped file that AI agents can search and quote, second by second. It runs on your machine.

Process once. Ask forever.

A transcript loses what was on screen. Screenshots lose what was said. VIDEOContext keeps every signal and the moment it happened, then saves it all to a single .vctx file next to your video.

  1. Resolve

    Take a file path or URL and fetch it safely to a local file.

    sources/

  2. Probe

    Read duration, frame rate and resolution.

    ffprobe

  3. Sample & cut

    Pull frames and detect where scenes change.

    ffmpeg

  4. Read the screen

    Extract on-screen text: code, slides, error messages.

    tesseract

  5. Transcribe

    Turn speech into timed segments, locally.

    faster-whisper

  6. Find events

    Spot errors, scene boundaries and UI changes.

    processing/events

  7. Write .vctx

    Save one document with per-stage status and provenance.

    schema/

Each stage is cached by content hash, stage version and config, so re-running is instant. If a dependency is missing, that stage is marked skipped and you still get a document. Nothing fails silently.

One file, every fact timestamped.

      
The .vctx document is the contract. Everything upstream produces it, everything downstream reads it. Search, timelines, graphs and context packages are computed from it on demand and never written back.

Start & end
Every stored fact carries start and end in seconds. Answers copy them; they never invent new ones.

        
Provenance
The document records which provider ran each stage, and whether it succeeded, was skipped or was partial.

        
Honest labels
Inferred output, like chapter titles, is marked inferred. Weak links are marked ambiguous.

        
Compatible
New fields are additive. Older files keep loading, and version changes go through a migration.

Built for coding agents.

    
Open your agent in a folder with a video and ask a question. It inspects the file, analyzes it once, locally, and answers with timestamps it can point to.

    

      

        
Claude Code

        
Install the skill, then ask in plain words or call it directly.

        videocontent init-agent
        /videocontent analyze demo.mp4
        
Or as a plugin: /plugin marketplace add AAGAM17/VIDEOContext

      

      

        
Codex

        
Same skill, installed where Codex looks for it.

        videocontent init-agent --agent codex
        $videocontent analyze demo.mp4
      

      

        
Any MCP client

        
A built-in stdio MCP server. No extra packages needed.

        videocontent mcp
        videocontent init-agent --agent agents

Text pulled from a video is treated as untrusted data, never as instructions. Agent output carries a content notice, redacts credential-shaped strings and is size-capped.

Strict layers, one direction.

      
Lower layers never import from higher ones. Extractors are pure functions behind protocols; the pipeline owns ordering, caching and degradation. Every surface is a thin peer on the same SDK.

      
Providers resolve in order: an object you pass in, then config, then a VIDEO_CONTEXT_* environment variable, then a local offline default. Register your own with @register_ocr("name") or the videocontent.plugins entry point.

What it promises.

    
These hold across every command, the API and the agent tools.

    
    
      
  • Local by default
    Nothing touches the network unless you opt into a cloud provider. The document records which one ran.
    • 
      
  • Evidence, not vibes
    Every answer traces back to spans with real timestamps from the video.
    • 
      
  • Inference is labelled
    Chains mean sequence, not cause. Guesses are marked as guesses.
    • 
      
  • Private logs
    Logs contain identifiers, timings and counts. Never transcript, screen text or frames.
